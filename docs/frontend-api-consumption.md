# Frontend API Consumption

Supexon frontends consume the API through `@supexon/tuyau`. Apps should not configure Tuyau, import generated API registry files, or call `fetch` directly from feature code.

## Imports

Use the app shim when working inside ERP, CRM or PDV:

```ts
import { api, createSupexonApiClient } from '@/lib/api'
import type { Data } from '@/lib/api'
```

Shared packages can import the boundary directly:

```ts
import { api, createSupexonApiClient } from '@supexon/tuyau'
import type { Data } from '@supexon/tuyau'
```

`@supexon/tuyau` owns the direct imports from `@tuyau/core/client`, `@supexon/api/registry` and `@supexon/api/data`.

## Base URL

Frontend apps read the API base URL from `VITE_API_URL`.

```dotenv
VITE_API_URL=http://localhost:3333
```

When `VITE_API_URL` is not defined, the shared client falls back to `http://localhost:3333` for local development. Tests or custom bootstraps can pass an explicit `baseUrl` to `createSupexonApiClient`.

## Generated Contracts

API registry and data contracts are generated by the Adonis API build/codegen flow. Do not edit files under `apps/api/.adonisjs/**` manually. If contracts are stale, run the API build/codegen command and fix source routes, controllers or transformers.

## Guardrail

Run the boundary check before merging frontend API integration work:

```bash
pnpm check:api-boundaries
```

The guard rejects direct `fetch(` usage, direct `@tuyau/core` imports from frontend apps and standalone app-local API client factories outside the approved `src/lib/api.ts` shim.
